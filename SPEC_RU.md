# Изменение ТЗ: GeoHide Switch 2.2.1

Имеет приоритет над дополнением 2.2.0 ниже. Ссылка HTTPS на подписку (включая Portal CP-035) загружается явно по кнопке импорта. Принимаются UTF-8 списки URI и их обычный/URL-safe Base64; ответ ограничен 1 МБ и 1024 профилями, загрузка — 20 секундами, перенаправления — тремя переходами только на HTTPS. Проверка TLS не отключается. Отмена и уход из приложения отменяют запрос; поздний результат не меняет конфигурацию.

После загрузки пользователь выбирает один совместимый профиль. Поддерживаются прежние SS AEAD, VLESS TLS/REALITY и Trojan TLS; raw нормализуется в TCP. XHTTP, неподдерживаемые протоколы, открытый VLESS и отключённая проверка сертификатов пропускаются с отдельными понятными причинами. Никакой скрытой подмены транспорта или снятия защиты нет. Совместимость формата не объявляется проверкой доступности внешнего сервера.

Сохраняется только выбранный outbound, зашифрованный Android Keystore. URL подписки и остальные профили не сохраняются и не попадают в диагностический отчёт. Unit-приёмка: текст/Base64, дубликаты, фильтрация, границы размера/числа профилей, HTTPS/сертификат/перенаправления и отмена. Android 15/16: HTTPS-импорт через реальный интерфейс, выбор профиля, шифрованное сохранение и отсутствие ключей/URL в отчёте; прежние сценарии сохраняются. APK 2.2.1 подписать постоянным ключом 2.2.0, чтобы обновление устанавливалось поверх.

# ТЗ: GeoHide Switch 2.2.0

Это дополнение имеет приоритет над историческими ТЗ ниже. Код 2.1.1 расширяется без пересоздания приложения.

1. Режим Авто (отдельный от ручных HTTPS/TLS/UDP): DNS-AI сначала TLS, затем HTTPS; другие профили сначала их шифрованный стандартный режим, затем другой шифрованный режим. Открытый UDP и другой провайдер автоматически не используются. Интерфейс показывает реально отвечающий транспорт. Выбор провайдера включает его стандартный ручной режим, как в 2.1.1; Авто включается пользователем явно.
2. Профили Wi-Fi / мобильная / другая сеть: раздельные выбранные DNS/режим и последний успешный шифрованный транспорт. Без SSID, геолокации и чтения истории. При смене активной физической сети применять соответствующий профиль, разорвать старые пуловые соединения, повторно проверить DNS. Сетевые события объединяются, незавершённые операции отменяются при STOP.
3. TLS-пул: ограниченные переиспользуемые соединения, сериализация запроса на каждом соединении, проверка вопроса/ID, никаких общих очередей с неограниченным ростом. Неисправные и старые соединения закрываются; STOP и смена сети закрывают весь пул. Сохранить проверки сертификата/hostname.
4. Проверка сервисов: явная кнопка запуска; этапы DNS, TCP, TLS/HTTPS; фиксированные публичные контрольные адреса и результат HTTP с временем, без обещаний входа в аккаунт. 403/429 не маркируются как доказанная блокировка. Ограничить время, число запросов и размер ответа; отмена при уходе/STOP. Пользователь видит различие DNS доступен / сервер доступен / сайт ответил.
5. Диагностика: ограниченный журнал событий без произвольных DNS-имён, ключей, конфигураций VPN, cookies, заголовков авторизации и истории посещений. Кнопка сохраняет UTF-8 отчёт через Android Storage Access Framework. Журнал показывает транспорт, тип сети, категорию ошибки, число ответов и результаты контрольных тестов.
6. Полный VPN: отдельный режим в том же приложении; sing-box 1.14.3 + hev-socks5-tunnel 2.18.0, проверенные официальные исходники/контрольные суммы. Импорт ss:// (современные AEAD), vless:// с TLS/REALITY, trojan:// с TLS, либо sing-box outbound JSON тех же типов. Запрет отключённой проверки сертификатов, незашифрованного VLESS, SS none/legacy cipher, неизвестных плагинов. Внешний рабочий сервер предоставляет пользователь. Импорт хранят зашифрованно Android Keystore; конфигурации не попадают в отчёт. Корневой конфиг собирает приложение; неизвестные root-конфиги не запускаются.
7. В VPN-режиме IPv4/IPv6 и TCP/UDP направляются через ядро; DNS 1.1.1.1 проходит внутри выбранного прокси-туннеля. DNS-AI/GeoHide — отдельный DNS-режим, а не дополнительный одновременно работающий VPN. Само приложение исключено из полного TUN для исключения петли ядра; контрольные HTTPS-запросы в VPN-режиме явно идут через локальный аутентифицированный прокси. UI показывает это различие. Один активный VpnService, явный STOP закрывает TUN, native tunnel и дочерний процесс. Состояние включено только после проверки ядра/прокси; доступность назначения фиксируется отдельно.
8. Подпись: создать постоянный ключ, сохранить приватную резервную копию отдельно от git и отчётов; финальный APK подписывать одним ключом локально. Старую 2.1.1 с временным ключом нужно удалить один раз; дальнейшие версии с этим постоянным ключом обновляются поверх. Поставка APK и точный QA без обещаний универсального обхода DPI или белых списков.
9. Приёмка: unit-тесты Auto fallback без смены провайдера, TLS reuse/cancel, раздельных профилей, ограничений импорта и удаления секретов из отчёта. Android 15/16: прежние сценарии, Auto через TUN, ручной режим, сеть, экспорт отчёта, запуск/остановка полного VPN, TCP/UDP через native core на локальном Shadowsocks-сервере. Нативные ABI arm64-v8a, armeabi-v7a и x86_64; проверить ELF 16KB и подпись. Физический оператор/внешний аккаунт отдельно не считаются проверенными.

# Изменение ТЗ: GeoHide Switch 2.1.1

Имеет приоритет над дополнением 2.1.0. При выборе DNS-AI автоматически включается TLS (DoT); при выборе Cloudflare, AdGuard или Quad9 — HTTPS (DoH); при выборе GeoHide — прежний стандартный UDP. Настройка предыдущего провайдера не переносится. Даже если для профиля ранее вручную выбирался другой режим, повторный выбор профиля включает стандартный режим. Ручная смена транспорта возможна и сохраняется при перезапуске до следующего выбора профиля. Старое сохранённое HTTPS-подключение DNS-AI из 2.1.0 однократно переводится на TLS. После миграции последующие ручные изменения не переопределяются. VersionName 2.1.1, versionCode 20101. Проверка переключения в интерфейсе, миграции и TLS через VPN на Android 15/16 обязательна.

# Дополнение к ТЗ: GeoHide Switch 2.1.0

Актуальная версия от 13.10.2026. Разделы ниже, относящиеся только к 2.0.0, сохранены как история; новые требования этого дополнения имеют приоритет.

1. До включения VPN доступны выбор провайдера (GeoHide, DNS-AI, Cloudflare, AdGuard, Quad9) и поддерживаемого транспорта. Профиль и транспорт сохраняются; во время подключения и работы изменения заблокированы. Экран отображает профиль реально запущенной сессии.
2. DNS-AI подключается к dns.dns-ai.ru по HTTPS/443 либо TLS/853; UDP для него запрещён. Адреса и назначения профилей: DNS_PROVIDERS_RU.md. HTTPS — режим по умолчанию новых профилей; GeoHide сохраняет прежний UDP.
3. HTTPS использует OkHttp 5.3.2, бинарный POST DNS-message, HTTP/2 при поддержке сервером. TLS — стандартное length-prefixed DNS/TCP. TLS-имя и цепочка сертификата проверяются, все исходящие сокеты защищены от петли в VPN. Для первичного соединения используются IP только выбранного провайдера. Redirect и понижение до HTTP запрещены, ответы проверяются по MIME, размеру и DNS-вопросу. Между провайдерами нет автоматической подмены.
4. Сохранить явную команду STOP, закрытие TUN, UDP/TLS/HTTPS-сокетов и запросов, уведомление, полную отмену незавершённого подключения. HTTPS-запрос ограничен 6 с; TLS-попытка — максимум 3,5 с, общий цикл ограничен бюджетом 6 с плюс последняя попытка. Контрольный домен example.com не связан с конкретным провайдером.
5. Приёмка: прежние unit-тесты пакетов и UDP/TCP; сертификаты и hostname, DoH/DoT round-trip, отмена TLS/HTTPS, запрет redirects и неверных MIME/размеров; выбор DNS-AI, отсутствие UDP в его меню, сохранение при повороте, запрет изменения при работающем VPN, реальный пакет через TUN/HTTPS, отключение и выбор другого провайдера. Инструментальные проверки на Android 15/16. Доступность внешнего сервера из CI фиксируется отдельно и не заменяет проверку на телефоне.
6. Поставка: подписанный APK 2.1.0 (versionCode 20100), описание профилей и фактические результаты QA. Прежние ограничения локального UDP/TUN, одного VPN-слота и стороннего Secure DNS остаются.

# Техническое задание: GeoHide Switch 2.0.0

## 1. Назначение
Приложение Android для включения и отключения DNS GeoHide одной кнопкой. Продолжение проекта 1.0.1 с сохранением package/applicationId `dev.geohide.switcher`. Готовый результат — установочный подписанный APK, не требующий сборки пользователем.

GeoHide — сторонний Smart DNS с проксированием выбранных доменов. Приложение не обещает полный обход DPI, российских блокировок или работу всех сайтов. Оно не является официальным клиентом GeoHide.

## 2. Совместимость
Минимальная версия Android 9 (API 28), target/compile SDK 35. Приложение не содержит нативных библиотек и не зависит от архитектуры процессора. Android 16 должен поддерживаться платформенными API; подтверждение на физическом телефоне не заменяется заявлением о совместимости. Без root, ADB и изменения системных Private DNS-настроек.

## 3. Экран
- Фон #0B1113, основной акцент #CFFB7B, светлый текст.
- Круглая кнопка до 248 dp, уменьшение по доступной ширине; вся её площадь кликабельна.
- Значок питания рисуется Canvas: незамкнутое кольцо и вертикальная линия. Unicode-символ, emoji и зависимости от наличия глифа запрещены.
- Под значком внутри круга действие: «Включить» или «Выключить».
- Под кругом фактическое состояние и пояснение; далее адрес отвечающего сервера, число ответов и ошибок.
- Постоянная отдельная кнопка «Принудительно отключить» и ссылка на системные настройки VPN.
- Прокрутка, системные отступы, поддержка поворота и увеличенного шрифта. Доступное имя и роль кнопки для TalkBack.

## 4. Состояния
| Состояние | Условие | Основная кнопка |
|---|---|---|
| DNS выключен | Нет работающего сервиса и VPN | Включить |
| Разрешение VPN | Открыт стандартный диалог Android | Ожидание результата |
| Подключение | Запущена проверка DNS, VPN ещё не создан | Выключить |
| DNS включён | Проверка GeoHide успешна и VPN создан | Выключить |
| Нет ответа DNS | Туннель активен, запросы или контрольная проверка неуспешны | Выключить |
| Ошибка | Подключение не завершилось либо туннель аварийно закрыт | Включить |

Источник состояния — сервис, а не цвет кнопки и не сохранённый флаг. Экран сверяется с ним каждые 250 мс только пока видим. При создании нового процесса исходное состояние выключено; сервис не восстанавливается автоматически. Неуспешный контрольный ответ не выдаётся за работающий DNS.

## 5. Включение
1. Вызвать `VpnService.prepare`; при необходимости показать стандартное разрешение Android.
2. Отмена разрешения не создаёт VPN.
3. Запустить foreground-сервис с уведомлением.
4. Запросить A-запись `dnstest.geohide.ru` у GeoHide. Проверить идентификатор DNS, QR, вопрос, успешный RCODE и непустой ответ.
5. Создать DNS-only VPN: адрес 10.77.77.2/32, DNS 10.77.77.1, единственный маршрут 10.77.77.1/32, MTU 1500.
6. Обычный веб-трафик IPv4/IPv6 проходит по исходной сети; приложение не создаёт полный VPN-шлюз.
7. После создания TUN и успешного контрольного ответа показать «DNS включён».

## 6. DNS-обработка
- Стандартные системные DNS-запросы IPv4/UDP к виртуальному DNS пересылаются на GeoHide; сами запросы могут содержать A или AAAA.
- Серверы: 193.233.112.68, 193.233.112.67, 193.233.112.88, 45.155.204.190, 37.230.192.51, 46.8.158.6, 159.194.200.33. Резерв только среди GeoHide; скрытой подмены на другой DNS нет.
- Успешный сервер получает приоритет. Тайм-аут UDP 700 мс на попытку, общий цикл попыток ограничен бюджетом 5,5 с; последняя TCP-попытка может увеличить его примерно до 7 с.
- Все внешние сокеты защищены `VpnService.protect` от маршрутизации обратно в VPN.
- Если UDP-ответ усечён (TC), получить полный ответ с того же сервера по TCP/53.
- Проверять DNS-ответ и вопрос; некорректный ответ отбрасывать. Если все серверы недоступны, вернуть клиенту SERVFAIL и показать «Нет ответа DNS».
- Корректные IP/UDP checksum и фрагментация больших ответов под MTU 1500.
- Ограничить очередь 64 запросами и четырьмя работниками; переполнение возвращает SERVFAIL. Постоянного пустого busy-loop быть не должно.
- Проверка доступности каждые 15 с и при изменении физической сети. После восстановления ответа автоматически показать рабочее состояние.

Ограничения сетевого ядра: локальные запросы приложений по TCP непосредственно к виртуальному DNS, фрагментированные входящие IPv4-запросы и произвольные собственные DNS приложений не поддерживаются. Системный обычный DNS проверяется инструментальным тестом. Собственный DoH/Secure DNS браузера может обходить эту настройку. UDP/53 не шифруется. Системный строгий Private DNS и особенности прошивки проверяются на конкретном устройстве; приложение не меняет их без разрешения.

## 7. Отключение
Основная кнопка, отдельная аварийная кнопка и действие в уведомлении отправляют явную команду STOP одному и тому же сервису. Не полагаться на один stopService/onDestroy: Android удерживает работающий VPN-сервис через bind. Закрыть TUN, отменить исполнители и проверку, закрыть все активные UDP/TCP-сокеты, снять callback сети и foreground-уведомление. Переход к выключенному состоянию не ожидает ответа DNS. Сокеты и TUN одной сессии не должны закрывать ресурсы новой сессии. Повторное отключение безопасно.

Обработать `onDestroy` и системный `onRevoke`, включая замену VPN другим приложением. Возврат DNS происходит при удалении маршрута и DNS VPN; исходные системные настройки не переписываются. При отключении удаляется локальная DNS-подмена; уже закэшированные ответы сторонних приложений могут сохраняться до TTL.

## 8. Уведомление и Android lifecycle
Foreground-сервис типа specialUse с заявленным разрешением. На Android 13+ запросить разрешение уведомлений; отказ не запрещает включение DNS, но ограничивает видимость уведомления по правилам Android. Уведомление с векторной иконкой, состоянием и действием «Отключить». Сервис защищён BIND_VPN_SERVICE. START_NOT_STICKY. Always-on не поддерживается и явно отключён в метаданных. Другой VPN одновременно не поддерживается.

## 9. Приёмка
Автоматические проверки обязаны завершиться успешно до выдачи APK:
- Сборка, Android lint, проверка подписи APK.
- Unit: checksum, разбор и отбрасывание некорректных пакетов, SERVFAIL, фрагментация, закрытие заблокированного UDP-сокета, получение TC-ответа по TCP.
- Android-эмуляторы Android 15 и 16 (API 35/36): отмена разрешения; первое включение; реальный DNS-пакет через TUN с ответом локального тестового сервера; разрешение домена системным Android-резолвером через VPN; потеря ответа DNS и восстановление; поворот экрана; возврат в приложение; выключение и отсутствие VPN; пять повторных циклов; остановка во время проверки без ответа; быстрые нажатия; отсутствие уведомления после остановки.
- Сохранить скриншоты включённого/выключенного интерфейса и отчёты CI.

Ручные проверки на телефоне пользователя остаются отдельным этапом: работа GeoHide на Wi-Fi и мобильной сети, переключение Wi-Fi/LTE, выключенный экран/энергосбережение, другой VPN и системный отзыв разрешения. Их нельзя объявлять выполненными по результатам эмулятора. Ошибки доступности внешнего GeoHide не равнозначны ошибкам кнопки и отключения.

## 10. Поставка
APK, этот файл ТЗ, исходный проект и отчёт с фактически выполненными проверками. Использовать увеличенный versionCode. Если подпись предыдущего debug-APK отличается, указать необходимость удалить 1.0.1 перед установкой 2.0.0; не обещать обновление поверх несовместимой подписи.
